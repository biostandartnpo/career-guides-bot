# Лог инсайтов — накопленные закономерности

Это не сырые данные (те лежат в `content-factory/reports/`) — здесь только
**выводы, проверенные во времени**, отдельно от разовых находок одного прогона.
Разница с `topics-log.md`: тот про "что уже использовано, не повторять", этот —
про "что реально работает, стоит опираться при планировании".

Аналитик **обязательно** читает этот файл целиком перед каждым анализом (знать,
что уже проверяется) и обновляет его после: подтверждает/опровергает
существующие гипотезы новыми наблюдениями, добавляет новые. Контент-менеджер
читает его при планировании — подтверждённые инсайты приоритетнее разовых
находок текущего отчёта Аналитика.

## Статусы

- 🟡 **Гипотеза** — замечено один раз, нужно больше наблюдений, использовать
  с осторожностью.
- 🟢 **Подтверждено** — видно минимум на 2 независимых наблюдениях в разное
  время, можно уверенно опираться при планировании.
- 🔴 **Опровергнуто** — новые данные противоречат более ранним, гипотеза снята
  (запись остаётся в логе с этим статусом, чтобы не проверять её снова).

## Как обновлять

После каждого отчёта Аналитик:
1. Для каждой существующей строки — смотрит, есть ли в новых данных
   подтверждение или опровержение. При 2+ независимых подтверждениях меняет
   статус на 🟢. При явном противоречии — на 🔴 (не удаляет строку).
2. Добавляет новые гипотезы 🟡, если увидел что-то похожее на закономерность
   (не разовую случайность) в текущих данных.
3. Не путает частоту (одно и то же наблюдение, пересказанное дважды) с
   независимым подтверждением — подтверждение это отдельный пост/период,
   показавший ту же закономерность.
